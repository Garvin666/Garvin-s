## 如何维护

页面内容**全部**来自 `data/projects.js`，`index.html` 不含任何写死的项目信息。
因此更新内容不需要碰 HTML。

### 方式一：跑同步脚本（推荐，用于同步仓库数据）

```bash
python scripts/sync_projects.py            # 更新已收录仓库的星数 / 语言 / 更新时间 / 描述
python scripts/sync_projects.py --dry-run  # 只预览将要发生的变更，不写文件
python scripts/sync_projects.py --add-new  # 同时收录页面上还没有的新仓库
python scripts/sync_projects.py --prune    # 移除 GitHub 上已不存在的条目
python scripts/sync_projects.py --check    # 只校验数据完整性，不改动
```

- 每个条目的 `auto` 区块由脚本写入；`zh` / `highlight` / `tags` / `featured`
  等手工字段**永远不会被覆盖**。
- 仓库在 GitHub 上没填描述时，会保留你在本地补充的说明，不会被清空。
- 令牌按 `--token` → `GITHUB_TOKEN` → `GH_TOKEN` → `gh auth token` 自动解析，
  匿名访问也能运行（受每小时 60 次限流）。脚本不会记录或输出凭据。

### 方式二：直接改数据文件

改 `data/projects.js` 后刷新页面即可生效，无需构建：

- 加一个开源仓库 → 往 `repos.items` 里加一条
- 加一个站内 demo → 把页面放进 `demos/<名字>/`，再往 `demos.items` 加一条
- 改简介 / 技术栈 / 联系方式 → 改 `site` 与 `skills` 段
- 调整进行中的项目 → 改 `privateProjects.groups`
- 调整首屏那三个统计数字 → 改 `heroStats`（只填 `label` 与 `source`，
  **数值由集合实时派生**，不会写死）
- 开关交互能力 → 改 `ui` 段（见下）
- **「向下滚动」提示与联系表单 → 改 `index.html` 本身**（这两处是静态标记，**不在数据源里**）：
  提示是 `.scroll-cue`，表单是 `#contactForm`（字段 `#cfName` / `#cfMail` / `#cfMsg`，
  反馈区 `#cfNote` / `#cfLead`，蜜罐 `#cfTrap`），投递逻辑在脚本末尾的 `contactForm()` 里。
  **说明文字由脚本按投递方式改写，不要在 HTML 里硬写** —— 写死了就会与真实行为不一致。

### 联系表单的投递方式

由 `data/projects.js` 的 `site.contactForm` 决定：

```js
"contactForm": {
  "endpoint": "",                       // 留空 = 走 mailto；填了 = POST 到该地址
  "subject": "来自个人主页的留言"
}
```

| `endpoint` | 点「发送」后发生什么 | 页面上的说明文字 |
| --- | --- | --- |
| 留空（默认） | 组装一封真实邮件交给本机邮件客户端，收件人 / 主题 / 正文都填好 | 「会打开你的邮件客户端、内容已替你填好」 |
| 填了地址 | `POST` 表单编码到该地址，按返回结果显示成功 / 失败 | 「我会收到邮件」 |

几点需要知道：

- **收件地址不在这里配**：它从 `site.contacts` 里那条 `mailto:` 记录派生。
  同一个邮箱写两处，迟早会漂移成两个值。
- 提交时发的是 `application/x-www-form-urlencoded`，字段为
  `name` / `email` / `message` / `_subject` —— Formspree、Web3Forms、Formsubmit 都能直接吃。
- **`#cfTrap` 是蜜罐**：正常访客看不到也 Tab 不到，机器人会填，填了就静默丢弃。
  它刻意**保留 `display`**（只是移出视口 + 全透明），因为部分填表机器人会跳过 `display:none` 的字段。
  顺带一提：Playwright 的 `is_visible()` 不把 `opacity:0` 当隐藏，断言这类元素要直接查
  透明度 / 落点 / `aria-hidden`。
- 默认路径**不产生任何 http(s) 请求**（`mailto:` 是交给操作系统的协议交接，不是网络流量），
  所以「零外部依赖」的承诺不受影响；`endpoint` 路径的外部请求只在用户点发送时才发生。
- **mailto 的正文只在 `http(s)` 下写入来源页**（`file://` 打开时写「（本地预览）」）——
  否则会把本机绝对路径随邮件发出去。

### `ui` 配置段

`data/projects.js` 里的 `ui` 段是**真的会被读取**的能力开关（已由机器断言双向验证：
关掉后对应能力确实消失、内容仍完整）：

| 键 | 作用 | 关掉后的表现 |
| --- | --- | --- |
| `effects.aurora` / `mesh` / `grain` | 极光 / 网格 / 颗粒三层背景材质 | 对应节点被移除 |
| `effects.scrollProgress` | 顶部滚动进度线 | 不绑定监听，宽度保持 0 |
| `effects.stagger` | 子项 70ms 步进入场 | 子项直接显示，不分段延迟 |
| `effects.spotlight` | 卡片光晕跟随 | 不写入 `--mx` / `--my` |
| `effects.magnetic` | 按钮磁性位移 | 不绑定指针监听 |
| `effects.tilt` | 卡片 3D 微倾（±3° 内） | 不写入倾斜矩阵 |
| `effects.countUp` | 数字滚动计数 | 直接显示最终值 |
| `effects.viewTransitions` | 站内跳转的视图过渡 | 走普通跳转 |
| `commandPalette` | `⌘K` / `Ctrl+K` 命令面板 | `Ctrl+K` 不唤起 |
| `repoFilter` | 开源项目的语言筛选栏 | 筛选栏为空 |

两点提醒：

- **三层背景材质不受动效总开关影响。** 它们是静态装饰、本身不动，
  用户在「减少动态效果」下依然应当看到完整设计。其余动效项受总开关控制。
- **动效优先级是三级**：页面内显式选择 > 系统「减少动态效果」> 跟随系统。
  页脚的「动效」三段开关（跟随系统 / 开启 / 关闭）把选择落在 `<html>` 的
  `.motion-on` / `.motion-off` 上，值记在 `localStorage['gv-motion']`。
  切换后会**整页重载**（效果都在加载期绑定，热插拔的回归面远大于收益），
  重载前把滚动位置存进 `sessionStorage`，由脚本末尾接力回来。
  改动这条链时有三个地方必须同步，漏一处就会出现
  「JS 认为该播放、CSS 却把过渡清零」的自相矛盾状态：
  ① CSS 末尾「无障碍」段的 `html.motion-off` 与 `html:not(.motion-on)` 两套选择器；
  ② 脚本里的 `motion` 变量与 `on()`；③ 页脚开关的 `paint()`。
  为什么不能只写一条 `@media`：**媒体查询本身无法被页面内的选择推翻**，
  所以要让「强制关闭」恒定生效、「系统偏好」只在未被显式开启时才生效。
- `ui.theme` 目前只是**声明性标记**（记录本站为深色主题），改它不会切换配色。
  站内四页都是深色专项设计，没有做亮色变体。

### 方式三：加一个站内 Demo

1. 新建 `demos/<名字>/index.html`
   —— 资源用相对路径；返回主页的链接写 `../../index.html`（写成 `../../` 在本地 `file://` 下会落到目录列表）
2. 在 `data/projects.js` 的 `demos.items` 里追加一条，`href` 写 `demos/<名字>/index.html`
   —— 同理，写显式的 `index.html` 而不是目录名，`http` 与 `file` 两种打开方式才都走得通
3. 卡片可点与否**由有无 `href` 决定**：有 `href` 就渲染成可点卡片，
   没有则置灰并显示 `status` 文案（默认「计划中」）。
   `status` 是给人看的文案，`statusType` 是给脚本与统计用的机器值，两者别混用。
4. **加 `preview` 字段**决定卡片顶部的自绘预览块，取值为 `restaurant` / `studio` / `math`
   三者之一（对应 `index.html` 里的 `.pv-*` 规则）。没有 `preview` 的卡片不会画预览块。
   想加新样式就在 `index.html` 里补一条 `.pv-<名字>` 的 CSS 渐变规则，无需引入图片。

## 视觉与交互维护约定

全站（主页 + 三个 demo）共用同一套**手法与精度**，但允许各自配色不同 ——
主页 / 工作室站 / 数学工具站是深色，餐厅站刻意保留浅色暖调（这是作品多样性的一部分）。

改样式时请遵守以下约定，否则容易出现「局部被改好、整体不一致」：

- **设计令牌**：颜色、字体、缓动都走 CSS 自定义属性（`--bg` / `--ink` / `--purple` / `--ease` 等），
  不要在规则里写裸色值。换肤只改令牌即可。
- **三族字体混排**：标题走 `--serif`，正文走 `--sans`，数值与代码走 `--mono`。
  新增的等宽元素请用 `var(--mono)`，**不要另抄一份等宽字体栈** —— 各抄一份会导致
  本机装了 JetBrains Mono 时字形不一致。
- **对比度**：正文（含小字）文字对背景需 ≥ 4.5:1，大字（≥24px，或 ≥18.66px 且 bold）≥ 3:1。
  浅色主题里「装饰色」与「文字色」要分开：餐厅站的 `--copper` 只用于分隔线、图标、描边，
  承载文字与按钮底色的是更深的 `--copper-ink`。改配色后请用脚本复算，不要目测。
- **`prefers-reduced-motion`**：默认仍然尊重它，但**不要一刀切全禁**。
  真正该关的是位移 / 视差类动效；纯透明度淡入属于可保留范围。而且全禁之后，
  系统开了「减少动态效果」的访客打开站点会以为它坏了 —— 页脚那个「动效」开关就是为此存在的。
  新增动效时：把它接进 `on()`，并保证内容在「不做动画」时依然可见
  （不能用 `opacity:0` 起手却不兜底）。
- **对比度复算必须把 alpha 折算干净，两层都要**：
  ① 元素自身的 `opacity`（实际渲染色是 `fg*a + bg*(1-a)`）；
  ② **背景色的 alpha** —— 背景要逐层合成到不透明为止，不能取「最近一层非透明背景」就当实色。
  这两条各踩过一次：`.scroll-cue` 的 `opacity:.5` 让 5.28:1 掉到 **2.14:1**；
  页脚选中态按钮背景是 `rgba(...,.16)`，被误算成 **1.91:1**（实际 9.98:1）。
  另外，`opacity` 做「呼吸」时要取**一个完整动画周期内的最低值**，而不是拿静态色值算一次。
  同理，**复用旧版做法时语义可以照搬、参数不能照抄** —— 线上老版同一处用 `#555`（约 2.5:1），
  本来就不达标，照抄等于把旧缺陷一起搬回来。
- **零外部依赖**：不引入 CDN、外链图片或 Web 字体。图标用内联 SVG sprite（`<use href="#i-xxx">`），
  缩略图 / 意境图用 CSS 渐变自绘。
- **文案不要与行为脱钩**：能力变了就同步改文案，且尽量让文案由配置派生而不是硬写在 HTML 里。
  联系表单的说明文字就是脚本按 `site.contactForm.endpoint` 改写的 ——
  它曾经硬写着「不会真正投递」，而本轮起它真的会发出去，硬写死就变成说谎。

### ⚠️ CSS 渐变自绘的两个坑（都已踩过）

1. **径向渐变的末档必须全透明。**
   径向渐变在「结束形状」之外**不会停止**，而是继续铺最后一档颜色。
   所以 `radial-gradient(ellipse 8% 12.8% at 50% 46%, #f6e6c6 0 100%)` 会把**整张卡**刷成奶油色，
   把前面叠好的桌面、盘子、糕点全部盖住 —— 页面不报错、计算样式正常，但看起来就是一块空白。
   正确写法是补一个透明末档：`..., #f6e6c6 0 86%, rgba(246,230,198,0) 86%`。
2. **想要硬边就用成对色标。**
   `#fff 0 94%, rgba(255,255,255,0) 94%` 能切出锐利轮廓；
   纯靠颜色渐变收边会让物体糊成一团光晕，在浅色背景上尤其像「图没加载出来」。

餐厅站六张菜品图（`.shot-espresso` / `-latte` / `-pourover` / `-matcha` / `-basque` / `-croissant`）
就是按「桌面 → 投影 → 杯沿/盘 → 液面或糕点 → 高光」逐层叠出来的。
椭圆半径取 `rx 23% / ry 36.8%`：卡片是 16:10，`ry/rx = 1.6` 才会看起来是正圆。
换成真实素材时，只需替换这些 `.shot-*` 规则，页面结构不用动。

## 实现说明

- **零外部依赖**：图标为内联 SVG sprite，字体走系统字体栈，缩略图与意境图由 CSS 渐变自绘，
  不请求任何 CDN；断网也能完整显示。出站扫描可证：发布集内 `http://` / `https://` 出现次数为 0
  （唯一例外是页面运行时对 `api.github.com` 的静默刷新）。
- **数据与展示分离**：`index.html` 只负责渲染，内容全部来自 `data/projects.js`。
- **运行时静默刷新**：页面加载后会尝试从 GitHub API 拉取最新指标并就地更新；
  若被限流或断网，静默保留本地数据，不会有任何报错弹窗。
- **交互层**：滚动进度线、分段入场、导航滚动高亮、卡片光晕跟随、按钮磁性、3D 微倾（±3° 以内）、
  数字滚动计数、开源项目语言筛选、`⌘K` / `Ctrl+K` 命令面板、视图过渡。
  每个动效都受 `ui.effects` 开关控制；动效总开关由「页面内显式选择 > `prefers-reduced-motion` > 跟随系统」三级决定，
  页脚可一键切换并可记忆（详见上文「`ui` 配置段」末尾）。
- **无障碍与响应式**：支持键盘导航与可见焦点环、`aria-live` 状态反馈；
  在 375 / 768 / 1440px 三档下均无横向溢出。
